# Проверка Detector Danger на другом компьютере

Ниже описан способ проверить именно текущую локальную сборку, включая новый интерфейс,
RTSP и профили микрофонов.

## 1. Что перенести

Пока локальные изменения не отправлены в GitHub, обычный `git clone` скачает более старый
вариант. Для точного теста скопируйте всю папку `Detector_danger` на флешку, в архив или
облачный диск.

Можно не переносить:

- `.venv` — окружение всегда создаётся заново на целевом ПК;
- `.idea`, `__pycache__`;
- `data` — если не нужна старая база событий и логи;
- `detector_config.json` — если внутри есть RTSP-пароли или адреса объекта.

Нужно оставить исходники, `sounds`, `requirements.txt`, `setup.bat`, `run.bat` и
`install_and_run.bat`. Каталоги моделей можно перенести для экономии времени, но это
не обязательно: Vosk, Faster-Whisper, YOLO-Pose, PANNs и AST установятся автоматически.

## 2. Подготовка нового ПК

Требования:

- Windows 10/11 x64;
- интернет на время первой установки;
- около 3 ГБ свободного места для PyTorch, зависимостей и моделей;
- доступ к камере/микрофону в параметрах конфиденциальности Windows.

`install_and_run.bat` сам установит актуальный Microsoft Visual C++ Redistributable
x64 и официальный Python 3.12.10 x64, если их нет. Для установки Visual C++ Windows
может показать стандартный запрос контроля учётных записей. Уже установленный Python
можно указать явно:

```bat
set DETECTOR_PYTHON=C:\Python312\python.exe
```

Python Launcher (`py`) и заранее настроенный `PATH` не требуются.

## 3. Установка и проверка

1. Распакуйте проект, например в `C:\Detector_danger`.
2. Дважды щёлкните `install_and_run.bat`.
3. Первый запуск может занять 10–30 минут: будет создана `.venv`, установлены зафиксированные
   в `requirements.txt` зависимости,
   проверены/загружены модели и запущены тесты.
4. После установки запустите `verify_install.bat`. Он должен закончиться сообщением
   `Диагностика пройдена`, а тесты — `OK`.
5. Для следующих запусков используйте `run.bat`.

Если сеть оборвалась, просто повторите `setup.bat`: загрузки моделей и pip продолжатся.
Для отдельного восстановления ошибки `Failed to create a model` запустите
`repair_vosk_model.bat`. Путь проекта или имя пользователя могут содержать кириллицу:
загрузчик Vosk автоматически использует короткий Windows-путь либо поддерживает
ASCII-копию модели в общих документах.

## 4. Первичная настройка оборудования

1. Откройте `Настройки → Камеры и микрофоны`.
2. Для локальной камеры выберите её номер. Для сетевой камеры вставьте полный
   `rtsp://user:password@host:port/path`.
3. Назначьте каждой камере физически ближайший микрофон.
4. В разделе детекторов выберите речевой микрофон.
5. Нажмите `Профили микрофонов и автоматическая калибровка`.

Калибровку надо повторять отдельно для каждого микрофона и заново после его переноса,
смены усиления Windows, заметного изменения помещения или оборудования.

## 5. Как калибровать выстрелы

Выберите профиль:

- `Чувствительный` — тихая комната, где важны далёкие тихие импульсы;
- `Сбалансированный` — дом, офис, учебное помещение;
- `Строгий` — улица, цех, транспорт, помещение с дверями и постоянным шумом;
- `Пользовательский` — ручная настройка всех порогов.

Рекомендуемый замер — 15–20 секунд. Во время него должны звучать обычные помехи этого
места: речь, вентиляция, дорога, двери, клавиатура. Не создавайте специально очень
громкий удар прямо возле микрофона: он искусственно завысит порог.

После замера приложение рассчитывает:

- пиковый уровень фонового шума;
- RMS и требуемое превышение сигнала над фоном;
- обычную импульсность фоновых звуков;
- клиппинг;
- рекомендуемые пороги CNN и YAMNet для выбранного режима.

Если обнаружен клиппинг, уменьшите усиление/`Microphone Boost` в Windows и повторите
замер. Клиппированный сигнал теряет форму и часто похож на выстрел для нейросети.

## 6. Практический план испытаний

### Отрицательные сценарии

На протяжении хотя бы 30–60 минут воспроизведите обычную работу помещения:

- разговор и громкую речь;
- хлопки ладонями;
- закрывание дверей и шкафов;
- падение предметов и звон посуды;
- музыку/телевизор;
- пылесос, вентилятор, транспорт или производственное оборудование.

Записывайте длительность и количество ложных тревог. Главная эксплуатационная метрика:

```text
ложные тревоги в час = количество ложных тревог / время теста в часах
```

Для измеримого фонового теста без сирены и REST сначала посмотрите ID устройств:

```bat
.venv\Scripts\python.exe tools\audio_soak_test.py --list-devices
```

Затем оставьте приложение слушать обычную обстановку, например 30 минут:

```bat
.venv\Scripts\python.exe tools\audio_soak_test.py --minutes 30 --device 17
```

Утилита не сохраняет аудио; она выводит число тревог и тревог в час, а подробные решения
записывает в `data/audio_soak_stats.csv`. Для остановки раньше нажмите `Ctrl+C`.

Если ложных тревог много, сначала примените `Строгий` профиль и повторите калибровку.
Затем по одному увеличивайте `Порог CNN`, `Минимальный сигнал над фоном` и
`Минимальную импульсность`. Не меняйте сразу всё — иначе нельзя понять причину.

### Положительные сценарии

Для безопасного функционального теста можно воспроизводить размеченные записи выстрелов
через колонку с разной громкостью и расстоянием. Это проверяет программный и акустический
тракт, но не доказывает обнаружение настоящего выстрела: динамик иначе передаёт пик,
спектр и акустику помещения.

Испытания с настоящим оружием допустимы только законно, на оборудованном объекте и под
контролем ответственных специалистов. Для оценки качества нужны размеченные события,
precision, recall, задержка обнаружения и ложные тревоги в час.

### Остальные детекторы

- Произнесите каждое ключевое слово обычным, тихим и громким голосом, затем похожие, но
  нетревожные слова.
- Для падений проверьте приседание, наклон, завязывание обуви, лежащего человека и
  контролируемую имитацию падения на безопасный мат.
- Отключите RTSP-камеру на 1–2 минуты и убедитесь, что статус показывает переподключение,
  а после возврата сети изображение восстанавливается.

## 7. Что сохранить после теста

Для разбора результатов сохраните:

- `detector_config.json` без публикации секретов;
- `data/detector.log`;
- `data/detector_stats_*.csv`;
- `data/events.sqlite3`;
- время и описание каждого реального или ложного события;
- модель ноутбука, микрофона, камеры и описание помещения.

RTSP-пароли не отправляйте в GitHub, отчёты или скриншоты.
