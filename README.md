# Detector Dangerous

Локальное приложение для Windows, которое помогает оператору заметить опасные события в потоке с камер и микрофонов. Оно отмечает длительное горизонтальное положение человека, резкие звуки и заданные тревожные слова, сохраняет инциденты и показывает их в журнале.

В репозитории можно посмотреть обработку видео и звука, правила подтверждения событий, подключение моделей, журнал инцидентов и интерфейс оператора.

## Что происходит при событии

1. Приложение получает видео с локальной камеры, файла или RTSP-потока и звук с микрофона.
2. Видеомодуль анализирует положение человека во времени. Аудиомодуль сопоставляет звук с фоновым уровнем и проверяет заданные тревожные слова.
3. Подтверждённое событие попадает в журнал SQLite вместе со временем, источником и доступными материалами.
4. Оператор видит историю в интерфейсе PyQt6. При настройке внешнего адреса приложение отправляет уведомление через HTTP и видеоклип отдельным запросом.

Код разделён по задачам: `video/`: обработка кадров; `audio/`: микрофон и звук; `core/`: конфигурация, события, журнал и доставка; `ui/`: интерфейс. Такая структура позволяет проверять логику событий отдельно от камер и моделей.

## Запуск

Нужны Windows 10 или 11 и Python 3.12 x64. Первый запуск устанавливает зависимости и загружает общедоступные модели. Объём загрузки значительный; требуется подключение к интернету.

```bat
install_and_run.bat
```

Для настройки по шагам:

```bat
setup.bat
run.bat
```

Пример настроек находится в `detector_config.example.json`. Рабочий файл `detector_config.json` создаётся локально. Источником камеры может быть номер устройства, путь к видео или RTSP-адрес.

Проверка установки и тесты:

```bat
verify_install.bat
.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
```

Приложение рассчитано на настройку под конкретные камеры и акустическую обстановку. Пороговые значения и качество обнаружения нужно проверять на месте. В открытом репозитории нет рабочих адресов камер, учётных данных, записей, журнала событий и собственных весов моделей. Для проверки на конкретном объекте нужны его камеры, микрофоны и настройка порогов.
